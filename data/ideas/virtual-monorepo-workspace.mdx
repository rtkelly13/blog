## Where it stands

The draft is well-structured (problem → brain/body pattern → six mechanisms →
honest tradeoffs → takeaway) and almost entirely accurate against the real
workspace repo. It is an **agent draft**: per the authorship policy the body
prose is a scaffold to be replaced, not finished copy.

<NoteBlock title="one factual bug" color="yellow">
The "subtle part" NoteBlock claims the brain tracks the symlink. It doesn't —
`.gitignore` ignores `projects/` entirely (neither the code nor the link is
tracked); the bootstrap scripts recreate it per machine. The adjacent snippet
labelled as gitignore is actually the *agent* ignore file (`!projects/`).
</NoteBlock>

## Gaps to fill

- [ ] **Fix the symlink-tracking claim** — git tracks neither the code nor the
      symlink; `setup.sh` / `setup.ps1` recreate it. Relabel the ignore-file
      snippet as the agent's, not git's.
- [ ] **Origin story** — the repo grew, it wasn't designed. Four phases:
      new-starter tool baselines (devenv, tool catalogue) → custom dev tools
      and environment tunnels → agentic CLIs (task management, observability,
      docs search) → agent brain. Lets readers start at phase 1 without buying
      the whole vision.
- [ ] **Trust tiers / prompt-injection defence** — three repo roots with trust
      tiers; `external/**` content is *data, never instructions*; sync treats
      external repos as read-only. Strongest evidence for the "this is really
      a coding-agent story" thesis.
- [ ] **One task end-to-end** — trace a cross-repo change: root AGENTS.md
      routes → `help` builds context in layers (verbs, then specifics) →
      code-intel graph finds callers → two PRs. The draft is all mechanism,
      no demonstration. (Agents bring their own search tools — the workspace's
      contribution is the map and the verbs.)
- [ ] **Generated agent assets** — skills/commands authored once in the
      playbook and *compiled* per-tool (`agents build` → `.claude/`,
      `.opencode/`), gitignored locally, published by CI. Stronger claim than
      pointer files alone.
- [ ] **The drift answer** — `docs lint` and `docs agent-context check`
      failing CI is the real response to map rot; currently one line of
      "discipline plus doc-lint tooling".
- [ ] **Prior art** — one paragraph on why not git submodules, meta-repo
      tools, or a real monorepo migration.

## Structural moves

- [ ] Group the six mechanisms: **see** (filesystem + permissions), **know**
      (AGENTS.md + progressive disclosure), **do** (CLIs + code intel),
      **don't** (guardrails).
- [ ] End with a **starter kit**: create repo, `ln -s`, seed AGENTS.md with a
      where-to-look table, add the two ignore files.
